## Terminus custom indicators

```typescript
// v11 (removed)
export class DogHealthIndicator extends HealthIndicator {
  async isHealthy(key: string) {
    const badboys = await this.dogService.getBadboys();
    const result = this.getStatus(key, badboys.length === 0, { badboys: badboys.length });
    if (badboys.length) throw new HealthCheckError('Dog check failed', result);
    return result;
  }
}

// v12
@Injectable()
export class DogHealthIndicator {
  constructor(private readonly dogService: DogService, private readonly healthIndicatorService: HealthIndicatorService) {}
  async isHealthy(key: string) {
    const indicator = this.healthIndicatorService.check(key);
    const badboys = await this.dogService.getBadboys();
    return badboys.length > 0 ? indicator.down({ badboys: badboys.length }) : indicator.up();
  }
  ping(key: string) {
    return this.healthIndicatorService.check(key).attempt(() => this.dogService.ping()).withTimeout(1000);
  }
}
```

## @Optional in subclasses

```typescript
@Injectable()
class Child extends Base {
  constructor(@Optional() options?: Options) { super(options); }   // re-declare the marker
}
```

From 12.1, a subclass *without* its own constructor keeps its parent's markers again. 12.0.x dropped them in that case too, so upgrade to ≥ 12.1.

## Switching to ESM

`package.json`: `"type": "module"`. Projects generated with schematics ≥ 11.0.6 already have the right `tsconfig`. Older projects need `module`/`moduleResolution: "nodenext"`, `resolvePackageJsonExports: true` and `target: "ES2023"`. The complete set generated by `nest new` (ESM):

```json
{
  "compilerOptions": {
    "module": "nodenext", "moduleResolution": "nodenext", "resolvePackageJsonExports": true,
    "esModuleInterop": true, "isolatedModules": true, "declaration": true, "removeComments": true,
    "emitDecoratorMetadata": true, "experimentalDecorators": true, "allowSyntheticDefaultImports": true,
    "target": "ES2023", "sourceMap": true, "outDir": "./dist", "rootDir": ".", "incremental": true,
    "skipLibCheck": true, "strict": true, "strictPropertyInitialization": false,
    "types": ["vitest/globals", "node"]
  }
}
```

- CommonJS + Jest uses `"types": ["node", "jest"]`.
- `nest-cli.json` and `tsconfig.build.json` don't change.
- With `nodenext`, every file's emit format follows `package.json`. After adding `type: module`, expect every missing import extension to error at once, and fix them all in one pass.

## Moving code to ESM

| CommonJS | ESM |
| --- | --- |
| `import { AppModule } from './app.module'` | `'./app.module.js'` (the extension refers to the emitted file) |
| `__dirname`, `__filename` | `import.meta.dirname` (or `fileURLToPath(import.meta.url)`) |
| `require(x)` | `createRequire(import.meta.url)` from `node:module` |
| `bootstrap();` | `await bootstrap();` |

Also check custom bootstrap scripts, bundler configs, and test-runner configs that assume CommonJS.
